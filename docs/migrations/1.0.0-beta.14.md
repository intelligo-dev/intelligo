# Upgrading from 1.0.0-beta.6 to 1.0.0-beta.14

`1.0.0-beta.6` was the last version on npm before `1.0.0-beta.13`;
`1.0.0-beta.7` to `1.0.0-beta.12` were versioned but never published, so
an app on beta.6 takes all of them at once. This guide is that upgrade in
the order it is executed: packages, database, composition root, product
code, installed pages, then the checks. The detail behind each step is
in `CHANGELOG.md` under the versions named.

Do it on a branch, against a restored copy of the production database.
Keep `pnpm type-check` running from step 3 on: most of this upgrade is
the compiler telling you where a type moved.

## 1. Packages and peers

Every `@intelligo-dev/*` package moves together; mixing versions is
unsupported.

```bash
pnpm add @intelligo-dev/core@1.0.0-beta.14 @intelligo-dev/auth@1.0.0-beta.14 \
  @intelligo-dev/billing@1.0.0-beta.14 @intelligo-dev/executions@1.0.0-beta.14 \
  @intelligo-dev/chat@1.0.0-beta.14 @intelligo-dev/next@1.0.0-beta.14 # …every one you use
pnpm add -D @intelligo-dev/cli@1.0.0-beta.14
```

- **AI SDK 7.** `@intelligo-dev/chat` peers `ai@^7`. Move `ai` to 7,
  `@ai-sdk/react` to 4 and every `@ai-sdk/<provider>` to 4 in one step.
  The exports AI SDK 7 removed are rarely used by an app; `streamText`,
  `generateText`, `generateObject`, `tool`, `embed` and
  `DefaultChatTransport` are unchanged.
- **Next.js `~16.3.5`**: 16.2.x carries two unauthenticated
  remote-code-execution advisories.
- `@intelligo-dev/core` and `@intelligo-dev/chat` no longer peer `zod`,
  and `@intelligo-dev/admin` no longer peers `react-dom` — keep your own
  versions if your code uses them.
- **`@intelligo-dev/ui` is retired.** The registry design system
  replaced it (see [design-system.md](design-system.md)); remove the
  dependency. It still resolves at `1.0.0-beta.6` under `@beta`, so
  nothing warns you if you leave it.

## 2. The database

The framework's schema is now one baseline (`0000_baseline`) plus
`0001_reconcile_chain_built_databases` and what follows, applied by
`intelligo migrate` by content hash. Run `intelligo migrate --check`
against the restored copy first; it says which case you are in.

- **The database ran the whole pre-1.0 chain (48 migrations)** — `state`
  is `legacy` and `adoptable` is `true`. `intelligo migrate` records the
  baseline as applied without running it and applies `0001`, which
  reconciles the few places the old chain and the schema disagreed.
- **The database was migrated by `1.0.0-beta.6` from npm** — it ran the
  chain only through `0042_sessions_active_organization_id`, because the
  versions that carried `0043`–`0046` never reached npm. It is refused,
  and `migrate --check` names what it lacks (`legacyMissing`). No
  published version finishes that chain. The options — apply the missing
  SQL from your own copy, bring the schema to the baseline by hand and
  record it, or start from the baseline and move your rows — are in
  "Databases from before 1.0" in `@intelligo-dev/core`'s
  `src/db/migrations/README.md`. If `migrate --check` reports such a
  database as `ahead` with three unknown hashes, those are `0036`,
  `0038` and `0040` as beta.6 shipped them; the database is still a
  partial pre-1.0 chain.
- **The database was provisioned with `db:push`** — `state` is
  `unmanaged`. Baseline it as the same README describes, then migrate.
- **An empty database** — `state` is `fresh`; `intelligo migrate`
  applies everything.

What the schema no longer has, and what replaced it, matters to product
code that queried the tables directly:

| Table                 | Gone                                                   | Now                                                                                     |
| --------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| `usage_records`       | `cost`, `margin_multiplier`, `fx_rate`, `charged_mnt`  | `provider_cost_micros`, `margin_bp`, `usd_rate_micros`, `charged_micros`, `currency`    |
| `monthly_usage`       | `charged_mnt`                                          | `allowance_used_micros`, `currency`                                                     |
| `trial_credits`       | the three `*_mnt` columns                              | `initial_micros`, `used_micros`, `remaining_micros`, `currency` (token counters remain) |
| `credit_balances`     | `balance_mnt`, `total_purchased_mnt`, `total_used_mnt` | the same names in `*_micros`, `currency`                                                |
| `credit_purchases`    | `credits`, `amount`                                    | `granted_micros`, `granted_currency`, `price_minor`, `price_currency`                   |
| `credit_reservations` | `estimated_mnt`                                        | `estimated_micros`, `currency`                                                          |
| `billing_settings`    | `usd_to_mnt_rate`, `margin_multiplier_bp`              | `usd_rate_micros`, `margin_bp`, `currency`                                              |
| `executions`          | `charged_mnt`, `reserved_mnt`                          | `charged_micros`, `reserved_micros`, `currency`                                         |
| `finance_events`      | —                                                      | `amount_minor`, `currency`, `claimed_at`                                                |
| `user_quotas`         | the unique constraint on `user_id` alone               | unique `(user_id, workspace_id)`                                                        |
| `agents`, `documents` | `agents.product_type`, `documents.type_id`             | —                                                                                       |

Tables the framework no longer owns are gone from the schema and from
new databases (listed under "Features that left the framework" below).
An adopted database keeps them untouched; your own schema and migration
chain declare the ones you still use.

The scaffold's layout keeps the two chains apart: the framework's in
`drizzle.__drizzle_migrations`, applied by `intelligo migrate`; yours in
`drizzle.__app_migrations`, from `lib/db/schema.ts` and `./drizzle`,
applied by `drizzle-kit migrate`. `pnpm db:migrate` runs both.

## 3. Money is micros with a currency

Every amount in a public type is `Money` from `@intelligo-dev/core/money`:
`{ amount, currency }`, the amount in micros (millionths of a major
unit). `fromMajor(2000, "MNT")` is two thousand tugrik; `formatMoney`
renders one. A deployment states the one currency it bills in, and there
is no default exchange rate.

| beta.6                                                   | beta.14                                                                         |
| -------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `calculateCost()` → a USD number                         | `providerCost()` → `Money`                                                      |
| `calculateChargedMnt(model, in, out, margin, fx)`        | `chargeFor(model, in, out, rate)` → `{ providerCost, charged }`                 |
| `estimateWorstCaseChargedMnt`                            | `estimateWorstCaseCharge(model, rate)`                                          |
| `DEFAULT_BILLING_MARGIN = 4`                             | `DEFAULT_MARGIN_BP = 40_000`                                                    |
| `DEFAULT_USD_TO_MNT_RATE`                                | none — `BillingRate = { currency, usdRateMicros, marginBp }`                    |
| `PlanLimits.monthlyCreditMnt`, `getPlanMonthlyCreditMnt` | `PlanConfig.monthlyAllowance: Money`                                            |
| `TrialConfig.initialCreditsMnt`                          | `grant: Money \| null`                                                          |
| `hasActiveTrialMnt`                                      | `getActiveTrialGrant()`                                                         |
| `CreditBundle { credits, priceUsd }`                     | `{ grant: Money, price: Money }` — what the workspace receives, what it pays    |
| `ensureBillingSettingsRow()`                             | `ensureBillingSettingsRow({ currency, usdRateMicros, marginBp })`               |
| `getBillingOverview().creditBalance: number`             | `Money \| null`                                                                 |
| `QuotaCheckResult` / `SettlementOutcome` `*Mnt` fields   | `creditBalance`, `estimated`, `remaining` / `charged`, `plan`, `topup`, `trial` |
| `summarizeExecutions().totals.chargedMnt`                | `totals.charged: Money[]`, one per currency                                     |
| admin `chargedMnt24h`                                    | `charged24h: Money[]`                                                           |
| `formatPrice`                                            | gone — `formatMoney`                                                            |

`PlanConfig` also loses `descriptionMn` and `featuresMn`; plan copy in
another language lives in your message files. Amounts that are your
product's data (a salary, a tuition fee) are not billing money and stay
as they are.

## 4. The composition root

Compare `lib/intelligo.ts` with what `intelligo create` writes today
(`intelligo upgrade --check` shows whether the scaffold template moved).
What changed:

- **Seed the rows the registrations imply.** Nothing is seeded by a
  migration any more: call `ensurePlanRows()` and
  `ensureBillingSettingsRow(rate)` once per process, and retry on
  failure — the scaffold's `seedIntelligo()` does both, from
  `composeIntelligo()` and from `instrumentation.ts`. A database the old
  chain seeded (MNT at 3450, 4×) gets your configured rate instead;
  after first boot, `updateBillingSettings()` changes it.
- **The execution boundary is one call:** `createBillingExecutions()`
  replaces the ports a composition root used to assemble by hand
  (beta.14).
- **The workspace bootstrap is set here:**
  `setWorkspaceCreatedHandler(handler)`, which runs for every new
  workspace, the one signup creates included. The app-shell layout no
  longer passes it. The handler receives `{ workspaceId, userId, email }`.
- **Deleting a workspace cancels its subscription** only if you bind
  it: `createWorkspaceService` takes a `beforeDeleteWorkspace` port;
  bind `cancelWorkspaceSubscription` from `@intelligo-dev/billing`.
- **Register model prices.** `registerModels(DEFAULT_MODELS)`, or your
  own catalogue. An unregistered id is refused at admission with
  `unknown_model`, and the chat answers 503 `MODEL_UNAVAILABLE`.
- **The Stripe webhook** is `createStripeWebhookHandler()` from
  `@intelligo-dev/billing`, two lines in `app/api/webhooks/stripe/route.ts`.
  An event is marked processed only after its handlers succeed, so a
  failed one is retried.

Registries live on `globalThis`, so composing in `instrumentation.ts`
reaches every module in the process; a per-module "ensure composed"
import is not needed.

## 5. Product code

- **Auth guards throw `AuthGuardError`** with a `code`:
  `unauthenticated`, `no_workspace`, `forbidden`. Match on
  `isAuthGuardError(error)` and the code, not on the message.
  `requireWorkspace()` without a session is now `unauthenticated`.
  `requireFeature` throws `FeatureNotAvailableError`.
- **Chat error codes:** `MODEL_UNAVAILABLE` (503) for an unpriced model,
  where beta.6 answered 402 `QUOTA_EXCEEDED`; `BILLING_NOT_CONFIGURED`.
  Map both wherever you translate refusals.
- **Signatures:** `recordFeatureUsage(userId, workspaceId, action)` takes
  the workspace; `checkRateLimit(workspaceId, planSlug, endpoint)` takes
  a bucket; `listExecutions` requires `workspaceId`; the attachment
  services take the full actor; `checkFeatureQuota` returns
  `nearingLimit: boolean` where it returned a `warning` string;
  `startLocalPayment` no longer takes an amount (price the reference on
  the server); the email templates no longer take a `locale`.
  `DocumentListItem` gains `conversationId`.
- **`BilingualText` is `LocalizedText`** (`Record<string, string>`).
- **The chat turn** (`ChatTurnContext`) gains `write`, `updateMetadata`
  and `addUsage`: stream a part, patch the conversation's metadata, and
  hand over the tokens a tool spent on its own model call so the turn
  settles them. `createArtifactWriter` streams a document into the
  canvas. `ResolvedAgent` gains `providerOptions` and `generation`
  (temperature, output tokens, `toolChoice`, `prepareStep`, …).
- **Environment:** `BETTER_AUTH_SECRET` of at least 32 characters
  (`AUTH_SECRET` is accepted as an alias); `EMAIL_FROM` has no built-in
  default when an email provider is set; `APP_NAME` and `SUPPORT_EMAIL`
  brand the emails; `CRON_SECRET` gates the maintenance route.
  `intelligo doctor` reports what is missing.

## 6. Sync your pages with `intelligo sync`

Nearly every installed page changed: the chat item was rewritten, the
shell runs on `ai-sidebar` and scrolls inside `main`, the settings,
billing, usage and dashboard items render `Money`, and every primitive
is Base UI. Do not re-apply these by hand. `intelligo sync` installs
items from the registry bundled with the CLI — the pages of the same
release as your packages — in dependency order, puts your seams back
(`lib/*-config`, `lib/nav-config.ts`, …) and merges message files key by
key with your copy winning.

```bash
pnpm exec intelligo sync intelligo app-shell chat …   # name your items once
pnpm exec intelligo sync --check                      # afterwards, in CI
```

Name only the items you installed from the registry: a page your
product wrote at an item's path would be replaced. `sync` refuses to
overwrite a file edited by hand unless you pass `--force` — move what
the edit does into a seam first; if no seam can hold it, that is a seam
missing upstream. Things the sync cannot do for you:

- **Seams that grew.** `lib/shell-config.tsx` gains `sidebarContent`
  (bind `ChatHistory` there — the chat page no longer draws its own
  history column); `lib/chat-renderers.tsx` entries are
  `{ component, label, activity, sources, canvas }`, and the renderer
  actions add `addToolApprovalResponse`, `openCanvas`, `closeCanvas`;
  `lib/billing-config.ts` bundles are `{ grant, price }`.
- **The scaffold's own files.** `i18n/request.ts` returns the reader's
  time zone from `app-shell`'s `TimeZoneCookie`; without it every date
  stays UTC.
- **Other locales.** The registry ships English. After a sync,
  `intelligo sync --check` lists every key your `messages/<locale>/`
  files lack against the app's English copy (`locale-behind`); translate
  them.

## 7. Features that left the framework

These were one product's features inside the framework. Nothing in the
framework reads them any more; if your app uses one, it is yours now.

- **Referral** — `grantReferralUpgrade`, `recordReferralSignup` and the
  `referral_codes` / `referrals` tables. Declare the tables in your
  schema, attribute the signup from `setWorkspaceCreatedHandler`, and
  give the reward with `grantPlan()` (beta.14) —
  `{ workspaceId, planSlug, reason, actorId }` — which moves the plan through the billing
  service instead of writing `subscriptions` directly.
- **Generation quota** — `generation-quota.ts` is gone. Meter an action
  with the generic feature quota: give each plan a limit for the action
  (keyed by the action's name, or by a key `registerActionLimitKeys`
  maps it to), then
  `checkFeatureQuota(userId, workspaceId, plan, action)` before the work
  and `recordFeatureUsage(userId, workspaceId, action)` after it.
- **Knowledge and RAG tables** — `knowledge_articles`,
  `knowledge_documents`, `knowledge_chunks`, `rag_documents`,
  `pending_extractions`. Declare them in your schema and chain; the
  baseline still creates the `vector` extension, so a `vector` column
  works. The retrieval runtime and its embedding provider are yours.
- **Document types** — the `document_types` table and
  `documents.type_id`. A saved document carries a `kind`; classify titles
  through `lib/document-patterns.ts` (`registerDocumentPatterns`), and
  keep any richer catalogue in your own table.
- **Suggestions** — the `suggestions` table. A tool that proposes
  follow-ups stores them in your schema, or streams them to the page
  with `turn.write` without storing them at all.
- **Product tables** — `competitions`, `competition_entries`,
  `shared_reports`, `user_profiles`, `ee_audit_chain`, `image_tools`,
  `image_generations` and `agents.product_type`: declare what you use.

## 8. Check

```bash
pnpm type-check
pnpm exec intelligo doctor           # environment, composition root, item requirements
pnpm exec intelligo migrate --check  # the framework's chain applied
pnpm exec intelligo sync --check     # installed pages are the registry's
pnpm exec intelligo upgrade --check  # scaffold templates you have not taken
```

Then sign up, create a workspace, run a chat turn, buy credits against
Stripe's test mode and open the usage page: the charge appears there in
the currency you declared.
